# Zvon

Голос, демонстрация экрана и чат для компании друзей — внутри локальной сети или VPN (Radmin VPN, Hamachi, ZeroTier, Tailscale). Без облаков, аккаунтов и внешних серверов.

Один человек запускает Zvon в режиме **«Хост»**: у него поднимается сервер со встроенным медиасервером (SFU на mediasoup), чатом и хранилищем файлов. Остальные подключаются к нему по IP.

Работает на Windows 10/11, macOS (Intel и Apple Silicon) и Linux (Ubuntu, Fedora; X11 и Wayland). Рассчитан на компанию до 15 человек.

**Сервер в интернете (VPS).** Сервер можно поставить на арендованный VPS — тогда VPN не нужен, а приложение собирается в **онлайн-варианте** (без вкладки «Стать хостом»). На VPS вход идёт **по аккаунтам**: администратор создаёт логины, а ник, аватарку и пароль каждый меняет сам. Там же работает **веб-версия**: Zvon открывается в браузере на компьютере и телефоне по адресу сервера, без установки. Пошаговая инструкция: [deploy/README.md](deploy/README.md).

Веб-версия собирается командой `npm run build:web` (входит в `npm run build`) в `out/web`, её раздаёт сам сервер Zvon.

| Вариант | Как собрать | Для чего |
|---|---|---|
| `online` (по умолчанию в CI) | `ZVON_EDITION=online npm run dist` | Все подключаются к серверу на VPS |
| `lan` | `npm run dist` | Хост запускает сервер на своём компьютере (LAN/VPN) |

`ZVON_SERVER=адрес[:порт]` при сборке подставляет адрес сервера в поле подключения.

## Возможности

- **Голосовые каналы**:
  - индикатор говорящего;
  - выключение микрофона и звука;
  - громкость каждого участника;
  - выбор микрофона и динамиков;
  - эхоподавление и усиленное шумоподавление нейросетью (DeepFilterNet3): убирает стук клавиатуры, щелчки и фон даже поверх речи;
  - push-to-talk с глобальной клавишей.
- **Демонстрация экрана**:
  - выбор экрана или окна с превью;
  - 720p, 1080p или 1440p при 30/60 fps;
  - звук системы (где позволяет ОС);
  - несколько демонстраций одновременно;
  - полный экран и отдельное окно просмотра.
- **Камера** в голосовом канале.
- **Simulcast/SVC**: SFU отдаёт каждому зрителю подходящий по каналу слой качества, зритель может выбрать качество вручную. Невидимое видео не передаётся.
- **Текстовые каналы**:
  - история;
  - «печатает…»;
  - упоминания `@ник` и `@everyone`;
  - эмодзи;
  - редактирование и удаление своих сообщений.
- **Файлы**:
  - фото, видео и любые файлы до 500 МБ (лимит меняет хост);
  - перетаскивание и вставка из буфера обмена;
  - превью и просмотр фото;
  - встроенный видеоплеер с перемоткой;
  - прогресс загрузки.
- **Профиль**: ник и аватарка.
- **Уведомления ОС** о сообщениях и упоминаниях, звуки входа и выхода.
- **Трей и автозапуск**.
- **Панель хоста**:
  - участники с трафиком, отключение и блокировка;
  - управление каналами;
  - нагрузка медиасервера;
  - лимиты битрейта и размера файлов.
- **Безопасность**:
  - пароль комнаты;
  - сигналинг по WSS с самоподписанным сертификатом (доверие по отпечатку);
  - медиа шифруется DTLS-SRTP.

## Установка

Готовые установщики собирает CI (раздел «Сборка установщиков»). На GitHub они лежат в **Releases** или в артефактах последнего запуска **Actions**.

| ОС | Файл | Первый запуск |
|---|---|---|
| Windows | `Zvon-Setup-…-x64.exe` | SmartScreen предупредит о неизвестном издателе (сборка без платной подписи): «Подробнее» → «Выполнить в любом случае». |
| macOS, Apple Silicon | `Zvon-…-mac-arm64.dmg` | Перетащите Zvon в «Программы». Если macOS пишет «приложение повреждено» или «не удаётся проверить разработчика», выполните в Терминале `xattr -cr /Applications/Zvon.app`, затем откройте через правый клик → «Открыть». |
| macOS, Intel | `Zvon-…-mac-x64.dmg` | То же, что выше. |
| Linux | `Zvon-…-linux-x86_64.AppImage` | `chmod +x Zvon-*.AppImage && ./Zvon-*.AppImage`. На новых Ubuntu может понадобиться `sudo apt install libfuse2`. |
| Linux (Debian/Ubuntu) | `Zvon-…-linux-amd64.deb` | `sudo apt install ./Zvon-*.deb` |

**Разрешения на macOS.** При первом использовании macOS спросит доступ к микрофону, камере и записи экрана. Запись экрана разрешается в «Системные настройки → Конфиденциальность и безопасность → Запись экрана», после этого Zvon нужно перезапустить. Для push-to-talk вне окна нужен ещё «Универсальный доступ».

## Как стать хостом

1. **Сеть.** Установите VPN и создайте сеть, друзья входят в неё.
   - **Radmin VPN** — бесплатно, до 150 человек в сети. Проще всего, если все на Windows.
   - **Hamachi** — бесплатная сеть ограничена 5 участниками.
   - **ZeroTier** и **Tailscale** — работают на всех трёх ОС; лимиты бесплатных тарифов уточните на их сайтах.

   Если все в одной квартире или офисе, VPN не нужен — подойдёт обычная локальная сеть.
2. **Сервер.** Запустите Zvon, введите ник и откройте вкладку **«Стать хостом»**.
   - **Название сервера** — то, что увидят друзья.
   - **Порт** — по умолчанию `7777` (TCP: чат и сигналинг).
   - **Порт голоса** — по умолчанию `40000` (UDP и TCP: голос и видео).
   - **Лимит файла** — по умолчанию 500 МБ.
   - **Пароль комнаты** — очень желателен.
3. **Запуск.** Нажмите **«Запустить сервер»** — Zvon сам войдёт на ваш сервер.
4. **Брандмауэр.** На Windows Zvon проверит правила брандмауэра. Если их нет, нажмите **«Добавить правила»** и подтвердите запрос прав администратора.
5. **Адрес для друзей.** Отправьте друзьям адрес из списка «Адреса для друзей» — из той сети, где они сидят:
   - Radmin VPN — 26.x.x.x;
   - Hamachi — 25.x.x.x;
   - Tailscale — 100.x.x.x;
   - ZeroTier — адрес вашей сети.

   Если порт не 7777, добавьте его через двоеточие.
6. **Отпечаток.** Продиктуйте друзьям первые символы **отпечатка сертификата** (он показан там же). При первом подключении они его сверят.

Пока сервер нужен, приложение хоста должно работать. Его можно свернуть в трей. Если хост остановит сервер, друзья увидят «Восстановление связи…» и подключатся сами, когда он вернётся.

Управлять сервером можно из меню: клик по названию сервера вверху слева → **«Панель хоста»**.

### Какие порты открыть

Только у хоста. Друзьям ничего открывать не нужно.

| Назначение | Порт по умолчанию | Протокол |
|---|---|---|
| Сервер: чат, сигналинг, файлы | 7777 | TCP |
| Голос и видео | 40000 | UDP (основной) и TCP (запасной) |

- **Windows** — кнопкой «Добавить правила» в Zvon или вручную в PowerShell от администратора:
  ```powershell
  netsh advfirewall firewall add rule name=Zvon-Server-TCP-7777 dir=in action=allow protocol=TCP localport=7777 profile=any
  netsh advfirewall firewall add rule name=Zvon-Media-UDP-40000 dir=in action=allow protocol=UDP localport=40000 profile=any
  netsh advfirewall firewall add rule name=Zvon-Media-TCP-40000 dir=in action=allow protocol=TCP localport=40000 profile=any
  ```
  `profile=any` важен: сети Hamachi и Radmin Windows часто считает общедоступными.
- **Linux (ufw):** `sudo ufw allow 7777/tcp && sudo ufw allow 40000`
- **Linux (firewalld):** `sudo firewall-cmd --permanent --add-port=7777/tcp --add-port=40000/udp --add-port=40000/tcp && sudo firewall-cmd --reload`
- **macOS:** при первом запуске сервера нажмите «Разрешить» в запросе о входящих подключениях.

Если все в одной VPN-сети, пробрасывать порты на роутере не нужно.

## Как друзьям подключиться

1. **VPN.** Войдите в ту же сеть Radmin VPN, Hamachi, ZeroTier или Tailscale, что и хост. Убедитесь, что VPN показывает хоста «в сети».
2. **Подключение.** Запустите Zvon, введите ник. На вкладке **«Подключиться»** укажите адрес хоста (например, `26.12.34.56`) и пароль.
3. **Отпечаток.** При первом подключении Zvon покажет отпечаток сертификата. Сверьте его с хостом и нажмите «Доверять и подключиться».

Сервер сохранится в «Недавних серверах», пароль можно запомнить. Аватарка, поставленная один раз, сама появляется на любом сервере.

Если подключиться не получается — смотрите раздел «Если что-то не работает».

## Требования к каналу хоста

Весь трафик идёт через хоста: каждый участник отправляет ему один поток, а хост рассылает его остальным. Поэтому главное — **исходящая скорость хоста**.

| Что | Хост отдаёт одному зрителю | Пример на 10 человек |
|---|---|---|
| Голос, говорит один | ~50 кбит/с | ~0,5 Мбит/с |
| Голос, говорят все | ~50 кбит/с за каждого говорящего | до ~4,5 Мбит/с |
| Камера: крупно / в маленькой плитке | ~1,5 / 0,15–0,5 Мбит/с | — |
| Экран 1080p30 | до 3,5 Мбит/с | 9 зрителей ≈ 30 Мбит/с |
| Экран 1080p60 | до 5,5 Мбит/с | 9 зрителей ≈ 50 Мбит/с |
| Экран 1440p60 | до 9 Мбит/с | 9 зрителей ≈ 80 Мбит/с |

Что снижает нагрузку:

- молчащие почти не тратят трафик благодаря Opus DTX;
- демонстрации не передаются тем, кто не нажал «Смотреть»;
- видео в свёрнутом окне или в другом канале встаёт на паузу;
- зрителю с медленным интернетом SFU сам отдаёт слой пониже;
- при слабом канале хоста задайте в «Панели хоста → Лимиты» поле «Исходящий поток к участнику», например 4000 кбит/с.

Ориентир: для голоса хватит 5 Мбит/с исходящей скорости, для одной демонстрации 1080p на 5–8 зрителей нужно 30–50 Мбит/с.

VPN-сервисы иногда пускают трафик через свои ретрансляторы, и тогда скорость ниже, чем при прямом соединении.

## Если что-то не работает

| Проблема | Что проверить |
|---|---|
| «Хост отклонил подключение» | Сервер не запущен или указан не тот порт. |
| «Хост не отвечает» | Неверный IP; вы не в одной VPN-сети; брандмауэр хоста блокирует TCP 7777. Проверьте `ping <IP хоста>`. |
| Чат работает, а голос висит на «Подключение к голосу…» или «Восстановление связи…» | У хоста закрыт порт голоса 40000 (UDP и TCP) — добавьте правила брандмауэра. |
| «Голос на сервере недоступен» | У хоста не запустился медиасервер, причина видна на вкладке «Стать хостом». Чаще всего порт 40000 занят — выберите другой. |
| Не слышно собеседника | Громкость участника (клик по нику), кнопка «наушники», выбор динамиков в настройках. |
| Не работает микрофон | «Настройки → Проверка микрофона». На macOS — разрешение в разделе «Конфиденциальность». |
| Пустой список экранов на macOS | Разрешите Zvon «Запись экрана» и перезапустите приложение. |
| Не захватывается экран на Linux с Wayland | Нужны `pipewire` и `xdg-desktop-portal` с бэкендом вашего окружения (`-gnome`, `-kde` или `-wlr`). |
| «Сертификат сервера изменился!» | Хост переустановил Zvon или удалил его данные — сверьте новый отпечаток. Если хост ничего не менял, не подключайтесь. |

**Логи** лежат в папке данных приложения:

| ОС | Папка |
|---|---|
| Windows | `%APPDATA%\Zvon\logs` |
| macOS | `~/Library/Application Support/Zvon/logs` |
| Linux | `~/.config/Zvon/logs` |

Данные сервера хоста хранятся в подпапке `host-data`:

| Что | Где |
|---|---|
| Логи сервера | `host-data/logs` |
| База | `host-data/zvon.db` |
| Файлы | `host-data/files` |
| Сертификат хоста | `host-data` |

## Разработка

Требования:

- **Node.js 22 LTS** и **Git**.
- **Инструменты сборки нативных модулей** — нужны, только если для вашей платформы не найдётся готовой сборки `better-sqlite3`, `uiohook-napi` или `mediasoup-worker`:
  - Windows — Visual Studio Build Tools с рабочей нагрузкой «C++»;
  - macOS — `xcode-select --install`;
  - Linux — `build-essential python3 python3-pip`, для `uiohook-napi` ещё `libx11-dev libxtst-dev libxt-dev libxinerama-dev libxkbcommon-dev`.

```bash
npm install          # mediasoup скачает mediasoup-worker; better-sqlite3 и uiohook-napi пересоберутся под Electron
npm run dev          # режим разработки с горячей перезагрузкой
npm run build        # сборка в out/
npm run app          # запуск собранного
npm run typecheck    # проверка типов
npm run test:server  # автотест сервера: 130 проверок (чат, файлы, голос, видео, панель хоста)
```

После первого `npm install` закоммитьте `package-lock.json` — тогда CI будет ставить ровно те же версии через `npm ci`.

### Несколько клиентов на одном компьютере

Каждый `--profile` — отдельный пользователь со своими настройками:

```bash
npm run build
npm run app -- --profile=host     # «Стать хостом» → «Запустить сервер»
npm run app -- --profile=alice    # подключиться к 127.0.0.1
npm run app -- --profile=bob
```

Чтобы не было эха, наденьте наушники или выключите микрофон у всех, кроме одного. На Windows камеру может одновременно открыть только одна программа.

### Сервер без интерфейса

Для постоянного сервера на всегда включённом компьютере:

```bash
npm run build
# Linux/macOS
ELECTRON_RUN_AS_NODE=1 npx electron out/main/server.js --data ./host-data --port 7777 --rtc-port 40000 --password секрет --name "Наш сервер" --max-upload-mb 500
# Windows (PowerShell)
$env:ELECTRON_RUN_AS_NODE=1; npx electron out/main/server.js --data .\host-data --port 7777 --rtc-port 40000 --password секрет --name "Наш сервер"
```

Дополнительные параметры:

- `--rtc-ips 26.1.2.3,192.168.1.5` — на каких адресах слушать медиа. По умолчанию на всех IPv4.
- `--announced-ip auto|1.2.3.4` — внешний IP, который сервер сообщает клиентам для голоса (сервер за NAT, облачный VPS).
- Любой параметр можно задать переменной окружения: `--rtc-port` → `ZVON_RTC_PORT`, `--data` → `ZVON_DATA` и т. д. Готовый Docker-вариант — в [deploy/](deploy/README.md).
- `--admin-token <строка>` — клиент, вошедший с этим токеном, получает права хоста.

## Сборка установщиков

### Локально, под текущую ОС

```bash
npm run dist:win     # Windows: release/<версия>/Zvon-Setup-<версия>-x64.exe
npm run dist:mac     # macOS: .dmg под архитектуру этого Mac
npm run dist:linux   # Linux: AppImage и .deb
```

Собирать нужно на той ОС и архитектуре, для которой нужен установщик. `mediasoup-worker` — нативная программа: `npm install` кладёт её под текущую систему, и именно она попадает в установщик.

### Через GitHub Actions, на трёх ОС

Сборку описывает файл `.github/workflows/release.yml`.

**Каждый push в `main` и pull request** запускает сборку на четырёх машинах:

| Цель | Машина | Результат |
|---|---|---|
| Windows x64 | `windows-latest` | установщик NSIS |
| macOS Apple Silicon | `macos-15` | DMG arm64 |
| macOS Intel | `macos-15-intel` | DMG x64 |
| Linux x64 | `ubuntu-22.04` | AppImage и deb |

Linux собирается на более старой Ubuntu для совместимости. На каждой машине CI проверяет типы, гоняет автотест сервера и выкладывает установщики в артефакты запуска.

**Тег `v*`** (например, `git tag v1.0.0 && git push --tags`) делает то же самое и вдобавок создаёт **черновик релиза** со всеми установщиками. Остаётся проверить его и опубликовать.

**Как в установщик попадает медиасервер:**

1. На каждой машине CI `npm install` скачивает готовый `mediasoup-worker` под её ОС и процессор. Если скачать не удалось, worker собирается из исходников — для этого CI ставит Python.
2. В `electron-builder.yml` worker вынесен из asar (`asarUnpack: node_modules/mediasoup/worker/out/Release/mediasoup-worker*`) вместе с нативными модулями `better-sqlite3` и `uiohook-napi`. Исходники и промежуточные файлы mediasoup в пакет не попадают.
3. При запуске собранного приложения main-процесс передаёт серверу путь к worker через `MEDIASOUP_WORKER_BIN` (функция `resolveWorkerBin` в `src/main/index.ts`).

**Устаревшие метки машин.** GitHub время от времени выводит образы из оборота, особенно с процессорами Intel. Если задача «macOS Intel» не стартует, замените `macos-15-intel` на актуальную Intel-метку из документации GitHub Actions. Если Intel-машин больше нет совсем, удалите эту строку из матрицы и собирайте установщик для Intel-маков вручную на Intel-маке командой `npm run dist:mac`.

**Подпись кода** не используется:

- Windows покажет предупреждение SmartScreen.
- На macOS приложение подписано ad-hoc (`identity: '-'`). Без этого Apple Silicon считает его повреждённым, но Gatekeeper всё равно предупредит при первом запуске.

Чтобы убрать предупреждения, нужны сертификаты: Authenticode для Windows, Apple Developer ID и нотаризация для macOS. Их подключают переменными `CSC_LINK` и `CSC_KEY_PASSWORD` в секретах репозитория. Для macOS тогда включите `hardenedRuntime: true` — нужные права уже описаны в `build/entitlements.mac.plist`.

## Архитектура

```
┌─────────────── ХОСТ (приложение Zvon) ───────────────┐
│ окно (React) ⇄ main-процесс (трей, PTT, брандмауэр)  │
│        │ wss://127.0.0.1                             │
│ ┌──── utilityProcess: сервер ─────────────────────┐  │
│ │ HTTPS: /health, /upload, /files (Range)         │  │
│ │ WSS /ws: сигналинг, чат, присутствие, админка   │  │
│ │ mediasoup: Worker → Router на голосовой канал   │  │
│ │ WebRtcServer: один порт 40000 UDP+TCP           │  │
│ │ SQLite: каналы, сообщения, файлы, настройки     │  │
│ └─────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
        ▲ TCP 7777 (WSS + HTTPS)   ▲ UDP/TCP 40000 (DTLS-SRTP)
   ┌────┴─────┐  ┌──────────┐  ┌──────────┐
   │ клиент   │  │ клиент   │  │ клиент   │   — то же приложение Zvon
   └──────────┘  └──────────┘  └──────────┘
```

**Путь медиапотока:**

1. Клиент захватывает микрофон, камеру или экран.
2. Поток становится **producer** на транспорте отправки mediasoup-client. Кодеки:
   - голос — Opus;
   - камера — VP8 simulcast;
   - экран — VP9 SVC или VP8 simulcast.
3. SFU хоста принимает поток один раз и для каждого зрителя создаёт **consumer** на паузе.
4. Зритель снимает паузу, когда поток действительно нужен:
   - голос — сразу;
   - видео — когда видна плитка;
   - демонстрацию — после «Смотреть».
5. Слой качества SFU выбирает сам по каналу зрителя и размеру плитки, либо по ручному выбору зрителя.

**Протокол** — JSON-кадры `{ t, id?, d }` поверх WebSocket. На запрос с `id` приходит ответ `{ t: 'res', id, ok, d | err }`, события сервера приходят без `id`. Все запросы и события описаны в `src/shared/types.ts`, проверка входящих данных — в `src/shared/schemas.ts` (zod).

**Структура репозитория:**

```
src/
  main/       главный процесс Electron: окно, настройки, доверие к сертификатам (TOFU),
              запуск сервера, push-to-talk, захват экрана, трей, автозапуск, брандмауэр
  preload/    безопасный мост renderer ↔ main (contextBridge), контракт в api.ts
  server/     сервер хоста: hub.ts (WebSocket, чат, админка), sfu.ts + voice.ts (mediasoup),

  shared/     протокол, константы, сетевые утилиты — общие для клиента и сервера
  renderer/   интерфейс (React + zustand): экран подключения, чат, голос (voice/engine.ts),
```

**Как добавить язык интерфейса:**

1. Скопируйте `src/renderer/src/i18n/en.ts` и переведите строки.
2. Добавьте язык в `src/renderer/src/i18n/index.ts`.

Новый язык появится в «Настройки → Приложение → Язык».

## Известные ограничения

- **Хост — единая точка отказа.** Если хост выключил компьютер или тот ушёл в сон, сервер недоступен. История и файлы хранятся только у хоста. Для постоянного сервера используйте режим без интерфейса на всегда включённой машине.
- **Звук системы при демонстрации:**
  - **Windows.** Работает, но захватывает весь звук компьютера, включая голоса собеседников из Zvon — они услышат себя с задержкой. Включайте звук для игр и видео.
  - **macOS 13 и новее.** Через ScreenCaptureKit. На части версий звук может не прийти — тогда демонстрация продолжится без звука, и Zvon предупредит.
  - **macOS 12 и старше.** Звука нет.
  - **Linux.** Через «Monitor»-устройство PulseAudio/PipeWire, которое выбирается в окне демонстрации.
- **Push-to-talk:**
  - Linux с Wayland: глобальные клавиши видны только над окнами X11, поэтому надёжнее держать окно Zvon активным;
  - macOS: нужен «Универсальный доступ».
- **Громкость участника** — не выше 100%: усиление сверх этого ухудшило бы эхоподавление.
- **Встроенный видеоплеер** не воспроизводит HEVC/H.265 и часть MKV. HEIC-фото с iPhone приходят файлом для скачивания.
- **Аппаратное кодирование H.264** не используется: в Chromium оно ведёт себя по-разному на разных ОС, поэтому для экрана выбраны VP9 и VP8.
- **Аккаунтов нет**: личность пользователя — случайный id на его компьютере. Блокировка в панели хоста держится до перезапуска сервера, поэтому от посторонних надёжнее защищает пароль комнаты.
- **Трей на Linux**: в GNOME нужен AppIndicator (в Ubuntu он включён). Без трея крестик закрывает приложение.
- **Автообнаружения серверов** (mDNS, broadcast) нет — в Hamachi и Radmin оно всё равно ненадёжно. Адрес вводится вручную и запоминается в «Недавних серверах».
- **Подписи кода нет**, поэтому Windows SmartScreen и macOS Gatekeeper предупреждают при первом запуске.
